THE PROBLEM

Two federal mandates ask the same question. Both are answered by hand, weeks late.

Naval Medical Center Portsmouth is a hospital — intensive care, operating rooms, ventilators. It is also a Department of Defense installation. One building, two legal obligations, and both of them turn on a single number: how long can this place run without the grid?

Today an engineer answers it by reading SCADA logs after the fact. When someone asks why the third floor went dark at 2:03, the honest answer is three weeks of archaeology and an educated guess.

96 hours is not a number we chose. It is the self-sustainment window hospitals are expected to plan for — power, water, fuel, staffing — without outside help.

§2925 wants outage duration, mission impact, and the load the installation would curtail to survive. The CMS emergency-preparedness rule wants a plan that is documented, tested, and reviewed. Neither is a dashboard. Both are a filing — recurring, budgeted, and mandatory.

That is the wedge. Infrastructure software gets bought when it produces a document someone is already legally required to produce.

HOW IT WORKS

The graph is the program. The model is the weather.

Islanding nobody wrote

Buildings, substations, generators and switchboards are graph nodes. Conductors are edges carrying one flag: passable. A walker crossing the campus is filtered to passable conductors, so a de-energized cable is not an edge it declines to take — it is an edge it cannot see.

There is no connected-components routine anywhere in the repository. Open a breaker and the campus fractures because traversal changed. That is the whole mechanism. 

# the only islanding logic that exists
visit [->:Conductor:passable == True:->];
visit [<-:Conductor:passable == True:<-];

Two model calls, and nowhere else

The adversary plans a failure chain, then writes down what it learned. Both are functions with a signature and no body. There is no prompt string in this project. 

def draft_scenario(view: Dashboard,

    -> ScenarioDraft by llm();

def reflect_on(attempt: str, result: str)
    -> LessonDraft by llm();

The graph knows kilowatts. It does not know that storm surge floods low ground first, or that a fuel truck needs a passable road — so an intact generator still runs dry. That is world knowledge, absent from every electrical dataset, and writing a plausible failure sequence requires it.

Memory is what makes it an agent

If round one hands round two a number, that is hill-climbing and needs no model. It hands over a sentence instead — a corrected belief about wiring it was never shown — and round two's opening move exists because of it.

Where the model is deliberately absent

Nobody accredits a language model to de-energize an intensive care unit. Curtailment is a sorted list and a while loop: highest tier first, largest load first within a tier, tier one never. If shedding runs out before the target is met, it reports a breach rather than touching tier one.

It sounds like a weakness. It is the sentence that makes the rest of the system trustworthy — the intelligence sits on the threat, because you cannot script what goes wrong.

And because every decision is a graph node with edges to its evidence, the filing writes itself. Each line cites the archive node it came from.

We measured what the model is worth

The fair challenge to any LLM in a loop is: would a search do this better? So we built the search. It gets the same failure mechanisms and the same plausibility gate, plus two things the adversary never gets — the complete element list, and unlimited rehearsals.

That makes it an upper bound on achievable damage, not a realistic attacker. The useful number is how close the adversary gets to that bound while planning from names and status alone.

It also cannot say why. It emits flood:X → fuel:Y and nothing else — no hazard, no account of itself. You cannot brief it, and you cannot file it.

Then it found what the exercise missed

A red-team transcript can only implicate what the adversary chose to hit. Searching everything exposes the gap — and on this campus four switchboards each strand critical care on a single strike, none of which the adversary ever tried.

THE MARKET

Crowded in hardware. Empty where the decision gets made.

Microgrid software is a busy category, and almost all of it sits either upstream of the outage or downstream of it. Our nearest neighbours are instructive precisely because neither one competes with us.

Gridware tells you the pole broke. Squid helps you plan what to build. Neither tells a hospital which wing to keep alive at 2 AM, or explains the decision afterward.

Why now, and why us

Adversarial testing of microgrids is already a funded federal research direction, and the reporting obligations are not optional. The buyer has a deadline and a budget line before we ever walk in.

Wedge, then expand

Start as the report generator — mandatory, budgeted, low risk, and it replaces three weeks of log archaeology. Once the graph of a facility is inside the tool, resilience planning and the live control layer are the same graph with more walkers on it.

A second site is one JSON file. Portsmouth and Walter Reed both run on the same simulator — nothing in it knows about any particular campus.
